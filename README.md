# Discord 화면 오버레이 번역기 (Windows 전용)

디스코드 클라이언트를 전혀 건드리지 않고, 화면 위에 별도의 투명 창을 띄워서
외국어 메시지 위에 번역문을 덮어씌운다. Windows UI Automation(스크린 리더가 쓰는
것과 같은 표준 접근성 API)으로 디스코드 창의 실제 텍스트와 화면 좌표를 읽어온다.

Vencord 같은 DOM 주입 방식과 달리 디스코드 프로세스를 건드리지 않는다. 화면
좌표를 OS 표준 API로 직접 읽어서, 그 좌표에 불투명 라벨을 그리는 방식이다.

## 실행 방법

### exe로 실행 (권장)

`build.bat`을 더블클릭하면 `dist\DiscordTranslator.exe`가 만들어진다. 이후로는
그 exe만 더블클릭하면 된다(바탕화면에 바로가기를 만들어도 좋다).

- 실행하면 우하단 **시스템 트레이 아이콘**이 뜬다.
- **종료 / 번역 숨기기**는 트레이 아이콘을 우클릭해서 고른다.
- 별도 창이나 콘솔이 없다. 오버레이 박스만 디스코드 위에 뜬다.

### 파이썬으로 직접 실행

```
pip install -r requirements.txt
python discord_screen_overlay.py
```

번역은 무료 비공식 Google 엔드포인트를 쓰므로 **API 키가 필요 없다.**

접근성 트리가 비어 있어서 아무 메시지도 안 잡히면(트레이 아이콘은 떴는데 번역
박스가 하나도 안 뜨면), `Win+Ctrl+Enter`로 내레이터를 켜서 트리를 활성화한다.
최신 디스코드에는 예전의 "스크린 리더 지원" 토글이 없고, 스크린 리더가 감지될 때
트리를 만든다.

> exe는 저장소에 커밋하지 않는다(63MB). 각자 `build.bat`으로 만든다.
> Windows SmartScreen이 처음 실행 시 경고할 수 있는데, 서명 없는 exe라 그렇다.
> "추가 정보 > 실행"으로 넘어가면 된다.

## 구조

- `discord_screen_overlay.py` — 본체 (스캔 → 번역 → 오버레이)
- `inspect_discord_tree.py` — 진단용. 실제 디스코드의 UIA 트리를 덤프해서
  스캔 속도/요소 개수/계층 구조를 실측한다. 필터가 안 맞을 때 여기서 시작한다.

## 실측으로 알아낸 것들 (설계의 근거)

`inspect_discord_tree.py`를 실제 디스코드에 돌려서 확인한 내용이다. 이 세 가지가
구현 방식을 결정했다.

**1. 창 전체 스캔은 너무 느리다.** `descendants(control_type="Text")`로 창 전체를
훑으면 407개 요소에 약 700ms가 걸린다. 갱신 주기를 못 따라간다.

**2. 메시지는 `chat-messages-` ListItem 안에 있다.** 실제 채팅 메시지는 전부
`automationId`가 `chat-messages-<서버ID>-<메시지ID>`로 시작하는 ListItem 아래에
있다. 이걸 앵커로 삼아 메시지 목록 컨테이너만 스캔하면 속도가 수십 ms로 떨어지고,
사이드바·채널목록·헤더 같은 오탐도 자연히 사라진다.

**3. 메시지 한 줄이 수십 개 Text 조각으로 쪼개진다.** 디스코드는 링크/멘션/
이모지/문장부호마다 별개의 Text 요소를 만든다. 예를 들어 한 문장이
`"...type "` + `"!smallping"` + `" in "` + `"🤖bots"` + `" to add/remove this role."`
로 나뉜다. 조각을 따로 번역하면 `"("`, `" in "` 같은 쓰레기가 번역되고 문맥이
깨진다.

그래서 조각을 **화면 y좌표(같은 줄)로 묶어서** 한 줄로 이어붙인 뒤 번역하고,
그 줄의 rect 위에 박스를 얹는다. 한 줄 안에서 쪼개진 조각은 다시 합쳐 문맥을
살리면서, 줄마다 위치는 정확히 맞는다.

## 구현 노트

- **유저명/타임스탬프/편집표시/반응숫자 제거**: 한 메시지 안에서 타임스탬프보다
  앞에 오는 텍스트를 유저명으로 보고 버린다. 나머지는 정규식/휴리스틱으로 거른다.
- **번역 비동기화**: 좌표 추적(스캔)과 번역(HTTP)을 분리한다. 스캔 스레드는 캐시만
  읽고, 없는 문장은 워커 큐에 넣는다. 줄 단위로 쪼개면 한 화면에 번역할 문장이
  10개 넘게 나오므로 워커를 여러 개(기본 4) 두고 동시에 처리한다.
- **실패는 캐시하지 않는다**: 번역 실패(네트워크/레이트리밋)와 "한국어라 번역
  불필요"를 반드시 구분해야 한다. 뭉뚱그려 `None`으로 캐시하면 일시적으로 실패한
  문장이 영원히 원문으로 남는다. 실패는 점증 backoff로 재시도한다.
- **박스 크기**: 위치(좌상단)만 원문에 맞추고, 크기는 `max(원문, 번역문에 필요한
  크기)`로 준다. 원문 rect에 고정하면 번역문이 길 때 글자가 잘리고 겹친다.
  원문이 한 줄이면 줄바꿈 없이 가로로, 여러 줄 문단이면 세로로 늘린다.

## 알려진 제약

- Windows 전용 (`pywinauto` UIA 백엔드, `ctypes.windll` 의존).
- 디스코드 창이 최소화되면 좌표를 못 읽어 오버레이가 갱신되지 않는다.
- 번역 캐시는 메모리에만 있어서 재시작하면 초기화된다.
- 무료 비공식 엔드포인트라 대량 호출 시 일시적으로 차단될 수 있다. 콘솔에
  `[translate] 포기` 로그가 잦으면 워커 수를 줄이거나 정식 API 키로 전환한다.
- 스크롤이 갱신 주기(기본 0.35초)보다 빠르면 박스가 잠깐 어긋나 보인다.
