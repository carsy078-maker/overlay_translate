# 스캔 성능 실측 결과

> `inspect_discord_tree.py`가 자동 생성한 벤치마크 결과입니다.
> 개인정보(서버명·유저명·메시지 본문)는 담지 않고, 수치와 구조만 기록합니다.
> 원본 덤프(`discord_tree_dump.txt`)는 개인정보 때문에 커밋하지 않습니다.

## 측정 환경

- OS: Windows-11-10.0.26200-SP0
- 측정 시각: 2026-08-06 20:05
- Discord 창 크기: 1296 x 728 px
- Python: 3.14.3

## 핵심 결과

| 스캔 방식 | 대상 | 평균 시간 | 개별 측정 |
|---|---:|---:|---|
| ① 창 전체 모든 요소 `descendants()` | 937개 | 543 ms | 1회 |
| ② 창 전체 Text `descendants()` (순진) | 418개 | **287 ms** | 280, 258, 323 ms |
| ③ 프로덕션: 보이는 메시지만 | 메시지 7개 | **101 ms** | 94, 108, 101 ms |

**→ ② 대비 ③이 약 2.8배 빠름 (287 ms → 101 ms)**

핵심은 두 가지다.

1. **메시지만 콕 집는다.** 메시지는 전부 `automationId`가 `chat-messages-`로 시작하는 ListItem 안에 있다. 이 앵커로 목록 컨테이너를
   특정하면 사이드바·채널목록·헤더·유저설정을 통째로 건너뛴다(오탐 제거).
2. **보이는 메시지만 파고든다.** 목록의 `children(ListItem)`은 값싸게 받고,
   화면 밖(off-screen) 메시지는 `descendants(Text)`로 파고들지 않는다.
   비용이 '전체 메시지 수'가 아니라 '화면에 보이는 ~십여 개'에만 비례한다.

> 참고: ②의 절대값은 채널마다 다르다. 긴 임베드가 많은 채널(예: 공지)은
> Text 요소가 400개를 넘겨 ② 스캔이 700 ms에 달하기도 한다. ③은 그런
> 채널에서도 보이는 메시지 수만큼만 일하므로 영향이 훨씬 작다.

## Text 요소 길이 분포 (창 전체 기준)

- 최소 0 / 중앙값 6 / 최대 82 글자

| 길이 구간 | 개수 |
|---|---:|
| 0-1 글자 | 136 |
| 2-10 글자 | 179 |
| 11-50 글자 | 101 |
| 51-200 글자 | 2 |
| 200+ 글자 | 0 |

짧은 조각(0~10글자)이 압도적으로 많다. 링크·멘션·이모지·문장부호가
전부 개별 Text로 쪼개지기 때문이다.

## 메시지 구조 (정제됨)

메시지 한 개(ListItem)가 실제로 어떻게 쪼개지는지 — 실제 텍스트 대신
조각의 종류와 글자 수만 표시한다. 한 문장이 여러 Text 조각으로 나뉘므로,
조각별이 아니라 **메시지 단위로 합쳐서 번역**해야 한다는 근거다.

```
ListItem  automationId = chat-messages-<서버ID>-<메시지ID>
    └─ Text  [본문          ]    34 글자
    └─ Text  [빈칸          ]     0 글자
    └─ Text  [빈칸          ]     0 글자
    └─ Text  [본문          ]     5 글자
    └─ Text  [문장부호/이모지    ]     1 글자
    └─ Text  [본문          ]     8 글자
    └─ Text  [문장부호/이모지    ]     1 글자
    └─ Text  [본문          ]    35 글자
    └─ Text  [본문          ]    18 글자

ListItem  automationId = chat-messages-<서버ID>-<메시지ID>
    └─ Text  [빈칸          ]     0 글자
    └─ Text  [타임스탬프       ]     8 글자
    └─ Text  [타임스탬프       ]    25 글자
    └─ Text  [빈칸          ]     0 글자
    └─ Text  [본문          ]     5 글자
    └─ Text  [문장부호/이모지    ]     1 글자
    └─ Text  [본문          ]     8 글자
    └─ Text  [문장부호/이모지    ]     1 글자
    └─ Text  [본문          ]    17 글자
    └─ Text  [본문          ]    18 글자

```

## 재현 방법

```
python inspect_discord_tree.py
```

디스코드를 화면에 띄운 상태로 실행하면 이 파일이 다시 생성된다.
메시지가 0개로 잡히면 `Win+Ctrl+Enter`로 내레이터를 켜고 재실행한다.
